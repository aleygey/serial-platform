# TUI 输入、搜索与宏操作

本文描述当前实现。`Ctrl-] a` 之类的快捷键表示：先按 `Ctrl-]`，松开后再按 `a`。文中的“右键”均指键盘右方向键 `→`，不是鼠标右键。

## 输入模式与焦点

| 场景 | 操作规则 |
| --- | --- |
| LINE 输入区 | 本地编辑整行。`Enter` 立即发送实际输入内容并追加当前机型 Profile 的 EOL，随后回到最新串口输出。 |
| Agent 正在运行 | 人工 `Enter` 仍然立即发送，不排队。服务端将其记为人工介入；Agent 后续写操作必须先读取变化后的上下文。`Alt-Enter` 不再有单独的排队/插队语义。 |
| RAW 输入区 | 按键按设备终端编码发送；方向键、删除键等不用于本地命令补全。输出以设备 RX 为准，不伪造本地命令回显。 |
| Agent 历史区 | 先用 `Ctrl-] h` 聚焦。上下选择，左右展开/折叠，`Enter` 查看对应输出；`Esc` 返回输入区。RAW 模式下不要在此焦点中输入设备命令。 |
| 本地弹窗 | 搜索、配置、宏编辑及 Run 接管审批优先接收按键；在弹窗里按 `Enter` 不等于向串口发送命令。 |

`Ctrl-] l` / `Ctrl-] r` 切换 LINE / RAW。普通终端界面中的 `Ctrl-D` 发送一个 `0x04` 字节，不追加 EOL、不发送也不清空 LINE 草稿；Agent 历史区获焦时也可发送。它是否被设备解释为 EOF 取决于设备终端程序，不能把发送确认等同于设备已经退出。`Ctrl-C` 发送 `0x03`；LINE 中还会清空本地草稿。弹窗中的控制键服从该弹窗的本地规则。

`PgUp` / `PgDn`、鼠标滚轮用于阅读串口输出。`Ctrl-] f` 回到实时尾部。`Alt-1…9` 或 `Ctrl-] 1…9` 切换串口；每个串口保留自己的未发送草稿。

## 人工命令历史、灰字建议与补全

人工输入历史由同一个 seriald 服务的平台共享，不按串口隔离。只记录已确认发送的人工 LINE 命令；Agent 命令、RAW 按键、`Ctrl-C` / `Ctrl-D`、批量透传粘贴不混入这份建议历史。空输入不记录。同一命令去重并更新最近使用顺序。该历史不是完整 TX 审计日志。

服务端最多保留最近 **10,000 条不同人工命令**；TUI 在后台按每页 2,000 条、最多 5 页读取完整的建议快照，以下四种操作共用这份最多 10,000 条的历史。后台启动后读取，并每 5 秒及本客户端发送确认后刷新；服务不可用时保留已有缓存，不阻塞输入。若翻页期间历史 revision 或服务身份变化，丢弃本轮不一致列表并等待下次刷新。开始于本地命令确认之前的迟到列表不能覆盖新确认历史；已确认但尚未出现在足够新 revision 中的本地命令也会暂时保留。

| 按键 | LINE 输入区行为 |
| --- | --- |
| 输入前缀 | 光标在行尾时，以灰字推荐最近的、区分大小写的历史前缀匹配。灰字不是草稿的一部分。 |
| `→` | 行中移动光标；行尾存在灰字时接受整条建议。 |
| `End` | 行中先移动到行尾；已在行尾且存在灰字时接受建议。 |
| `Enter` | 只发送实际草稿，绝不自动发送尚未接受的灰字。 |
| `Tab` | 打开可见的人工历史候选列表，不立即改写草稿。`Tab` / `↓` 选下一项，`Shift-Tab` / `↑` 选上一项；`Enter` 只回填，需再按一次才发送；`Esc` 取消候选。 |
| `↑` / `↓` | 浏览较旧/较新的人工命令；回到最新一项之后恢复浏览前的草稿及光标。选中后继续编辑，视为新的草稿。 |
| `Ctrl-R` | 输入文字搜索人工命令历史；再按 `Ctrl-R` 循环较旧匹配。`Enter` 只回填，`Esc` / `Ctrl-G` / `Ctrl-C` 取消并恢复原草稿。 |

普通左右移动、删除及软件光标按 Unicode 字素处理，避免将组合字符拆开。这是基于人工历史的命令建议，不是在设备上安装 zsh/Oh My Zsh：没有推断设备文件路径、当前目录或命令参数的远端 shell 补全。

## 同页机型配置

通过 `Ctrl-] o` 修改当前串口配置，或 `Ctrl-] m` 进入配置菜单。机型选择和机型目录管理都使用同页树状列表：一级机型在原列表中展开二级机型，不另跳二级选择页。

- 一级行：`Enter` / `→` 展开，`←` 折叠；展开本身不提交绑定。
- 二级行：`Enter` 选择并提交完整的一级、二级组合；`←` 回到父级。不能只提交一级机型。
- `Esc` 取消尚未提交的选择，保留原绑定。配置字段确认后立即提交；涉及共享 Profile 的影响仍需要确认，不能绕过共享修改提示。
- 目录中的“新增一级机型”“新增二级机型”仍有名称输入及校验；新增、删除和绑定不是同一种操作。

串口输出栏标题突出显示当前机型名，未配置状态单独显示，便于确认当前操作对象。

## 串口输出搜索

按 `Ctrl-] /` 打开输出栏右上角查找框，直接输入字符串。默认是**不区分大小写的字面搜索、当前串口、本次 TUI 会话**：例如 `.`、`[` 被当成普通文字，不会被误解为正则语法。

查找对应的是串口栏已经采用的同一份终端文本投影：ANSI 控制序列、分块 UTF-8 和回车覆盖先按显示规则处理，再匹配；不是原始字节搜索。设备自然回显的命令可在 RX 中找到，未回显的 TX 不会伪装成串口输出。用于限制超长行的内部切段不会让跨段字符串漏匹配，真正换行或流边界不会被任意拼成同一行。

| 按键 | 搜索行为 |
| --- | --- |
| 输入、删除查询 | 短暂防抖后后台查找，结果直接定位到串口栏并展示上下文。旧查询及迟到响应不会覆盖新查询。 |
| `Enter` / `F3` / `↓` | 下一个匹配。 |
| `Shift-Enter` / `Shift-F3` / `↑` | 上一个匹配。到首尾时循环。 |
| `Alt-C` | 切换大小写敏感。 |
| `Alt-S` | 切换当前串口本次会话、所有当前配置串口本次会话；有活动 Run 时还会经过 Run 范围。 |
| `Alt-R` / `Alt-D` | 切换正则/字面或方向过滤；见下方范围限制。 |
| `PgUp` / `PgDn` | 阅读命中附近的上下文，可继续加载更早/更晚的存档窗口。 |
| `Esc` / `Ctrl-C` | 关闭搜索并去掉高亮，保持当时阅读位置；仍可继续翻阅旧上下文。`Ctrl-] f` 才回到实时输出。 |

首次查找定位最新匹配，随后会跟随新匹配；手动切换过结果后保留所选位置。扫描中会显示进度状态，计数可能继续增长。完整性缺口与“扫描已结束”是两回事：有缺口时仍明确提示存档不完整，零匹配不能证明缺失的历史中没有目标字符串。

### 全会话范围与旧日志查询的区别

默认字面搜索不再受显示缓存的 **20,000 行 / 4 MiB** 上限限制。TUI 为当前打开的各串口维护独立磁盘存档；已经被显示缓存淘汰的行仍能查找和回载。正常流重置使用无损边界保存旧行，跨 daemon epoch 的已收集文本仍保留。

“本次会话”不是无限历史：它覆盖此 TUI 打开后已收到并成功归档的输出，以及启动时实际加载的有限历史；不承诺找回打开前未加载的全部日志，也不承诺补齐断线时无法重放的字节。从配置删除某个串口会结束其 Slot 的会话存档；关闭再启动 TUI 也不是接着打开上一次搜索存档。

当前全会话磁盘搜索只用于字面 RX/串口显示范围。切换到**正则、当前 Run 或 TX**时，界面明确标为“仅内存范围（正则/Run/TX）”，不能据此声称已查遍全会话。尤其 TX 不属于默认串口显示投影。这些选项也不会自动转为服务端所有历史 archive 的全量搜索。原有服务端 journal/archive 日志接口及 Agent 命令证据定位是另一条查询路径，其结果仍受实际日志保留情况和显式缺口约束。

### 存档成本、退出与故障

存档放在系统临时目录下独立的 `serial-platform-session-…` 目录；Unix 上目录权限为 `0700`。内容含串口文本，仍应按敏感日志对待。

- 磁盘占用随本次会话文本、行索引及查询结果增长，没有通过循环覆盖旧行来假装全量搜索；当前实现没有用户可配置的存档配额。高输出量、长时间运行时应关注临时磁盘空间。
- 显示缓存仍有界。写盘队列最多 256 项、16 MiB 预算；搜索命中索引落盘，单个匹配索引记录 32 字节，读取结果和上下文按窗口进行，不把全部命中放进内存。
- 追加和扫描在后台进行，刷新只处理新增数据及替换的未结束行，不每次重扫全部旧输出。关闭或更改查询会取消旧扫描。
- 正常释放最后一个存档引用后清理该临时目录。磁盘/队列故障会保留诊断目录；异常退出也可能留下临时文件，不应当作自动可续查的正式日志归档。
- 磁盘写入失败、队列饱和、服务报告 Gap、事件序列缺失均会明确提示覆盖不完整；不阻塞串口接收，也不悄悄把漏采后的零命中展示成完整“未找到”。请先检查空间、连接及日志状态，再用服务端保留日志核对缺失范围。

## TUI 宏目录与编辑

按 `Ctrl-] a` 打开宏页面。默认只列共享宏；新建宏默认保存为草稿，临时或尚未验证的内容不会自动进入所有 Agent 默认可见的共享列表。

| 页面/按键 | 行为 |
| --- | --- |
| 目录 `↑` / `↓` | 选择宏并读取对应固定版本的脚本。`PgUp` / `PgDn` 阅读长脚本。 |
| `n` / `e` | 新建 / 编辑所选宏。 |
| 编辑器 `F2` | 在脚本与属性 JSON 间切换；属性包含 ID、名称、用途、参数声明、适用机型及 `shared`。 |
| 编辑器 `Ctrl-S` | 校验并保存，不执行。修改已有宏使用原 revision 检查并发冲突；校验通过不代表已在真机验证。 |
| 编辑器 `Esc` | 保留本 TUI 内的未保存草稿并返回目录；再次打开编辑可恢复。未保存草稿不是服务端持久保存，退出 TUI 前需要主动保存。 |
| 目录 `a` | 编辑本次运行的参数 JSON；`Ctrl-R` 执行，`Esc` 返回。参数无效时不执行。 |
| 目录 `r` | 执行当前已保存、已读取的固定 revision，不偷偷执行未保存编辑内容；当前 TUI 运行超时为 30 秒。 |
| 目录 `x` | 请求停止当前宏；“正在停止”不是已经停止，需等待终态。 |
| `v` / `F5` | 切换是否包含草稿 / 刷新目录。 |
| 目录 `Esc` | 关闭页面，不等于停止正在执行的宏。 |

脚本中的 `cmd(...)` 使用当前机型 EOL。脚本语言及参数格式以宏接口文档为准；TUI 不提供一套不同的解释器。需要试运行修改时，先保存草稿版本，再运行；确认可复用且审核过用途、参数及机型适用范围后，才显式设为共享。

运行宏时，空闲串口可以申请临时人工控制权；已有本客户端人工控制权则复用。Agent 或其他人占用时不会暗中抢占，页面会提示先完成交接。宏终态后仅释放宏临时取得的控制权，原本持有的人工控制权或运行中人工输入后仍需继续使用的控制权不会被自动释放。

断线或启动响应丢失时，不自动重放宏。重连只查询已发送操作 ID 的状态；查不到执行记录会提示“无法证明设备未执行”，不能据此直接重试可能有副作用的操作。
