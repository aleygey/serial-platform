## 3. 平台共用历史与输入 UE（#11、#17、#18、#20）

### 3.1 数据与持久化

由 seriald 持久化人工输入历史，供同一平台的 TUI/App 共同浏览和补全，不按端口或机型隔离。历史绑定稳定 server identity，服务重启、端口切换和客户端重连后仍保留。此次不增加供 Agent 读取人工输入历史的 MCP 工具。

数据来源仅为人通过 LINE 输入框手动提交的完整命令（包括人从历史选取后再次提交）。Agent command/sequence、人工或 Agent 启动的宏展开步骤、RAW 单键/信号和设备 RX 回显均排除；不能仅依据 actor=Human 就把人工启动宏的步骤收进来，需保留明确输入来源。

人工历史按命令去重，保留最近使用时间和次数。上下键浏览和灰字建议都使用这份人工历史。端口、机型只用于显示来源，不影响默认候选可见性。草稿仍按输入区域/当前端口保存，避免切端口丢失未提交文本。

后端确认发送后按 operation id 去重持久化；这里表示命令已发送，不表示设备执行成功。明确拒绝保留草稿；不确定写入继续留在原有操作时间线，不自动进入普通补全或待重发草稿。记录在 journal worker 更新，不占用物理串口 writer。建议库保留最近 10000 条不同人工命令；达到上限明确提示，不能把它称为无限历史。客户端可通过有界查询/分页读取。

旧日志回填只能使用能够明确证明是人工 LINE 提交的完整命令元数据；无法证明来源的记录不猜测。现有 Agent 操作时间线保留原用途，与这份人工输入历史分开。

### 3.2 焦点与键盘规则

只有当前焦点区域处理编辑/导航键；弹窗、候选菜单、面板的优先级显式定义。标题、边框和光标共同标明焦点，避免只靠颜色。

### 3.3 编辑、补全和发送细节

- 初次向上浏览历史时保存草稿与光标；向下越过最新记录时恢复原草稿。切端口保留各输入草稿与浏览位置，但候选历史共享。
- 支持按词移动/删除、行首尾、Unicode 和长命令可视编辑。App 遵守 IME 组合输入，候选确认键不能同时触发串口发送。
- 灰字推荐复刻 zsh-autosuggestions 的 history 交互：输入非空前缀后，推荐最近一条匹配的人工历史后缀；不改变真实草稿。右方向键只在光标位于输入末尾、无选区且不处于 IME 组合输入时接受整条建议；在中间仍正常移动光标。End 在行中只移动到末尾，已在末尾时才接受建议。接受只填入文本，Enter 仅发送真实草稿，绝不发送未接受的灰字。输入框无焦点、RAW、IME 组合输入及有选区时不显示或接受灰字。
- Tab 保留候选菜单，灰字推荐与菜单补全分开。默认建议只来自人工历史，不加入 Agent 命令、宏步骤、本机 shell 的命令/文件；明确配置的词表可作为后续补充，不自动探测 DUT。宏使用独立目录/执行入口，不作为普通串口命令回填。
- 候选在本地有界缓存中异步/增量匹配；每次输入带版本，旧结果不能覆盖新草稿。空输入不出灰字，缩放、水平滚动、Unicode 字素和显示列宽保持一致。TUI 软件光标绘制需保留文本样式，App 用独立 overlay 显示后缀，不能把灰字写入 input value。
- Enter 统一即时 Human command。Agent 占用时沿用当前人工介入与 read gate，不恢复排队，不增加 Alt+Enter 分叉。
- 空 Enter 统一使用有效 EOL；有效 EOL 为空时保留当前 TUI 的 CR 回退规则，并同步 App 行为。普通命令自动使用 Profile EOL，避免二次追加。
- 粘贴单行进入草稿。多行显示完整预览和行数，显式选择编辑或发送；需要等待/循环的多步流程可转为宏草稿。确认框绑定原目标端口，切端口不能悄悄更换发送目标。
- 已发送请求采用稳定 operation id，明确拒绝保留草稿；断线或部分写入结果不确定时清除自动重发路径，保留结果提示和时间线入口。
- Ctrl-D 在非模态主界面与 Ctrl-C 一样作为人工控制操作透传，LINE/RAW 均只发 0x04；搜索、配置和其他编辑弹层保持按键隔离。Agent/宏活跃时复用人工介入和 read gate。它不清草稿、不记录输入历史，也不会退出本地 TUI。App 应调用独立 Human signal/raw-byte 内部通道，不能把控制字节送进会追加 EOL 的普通命令接口。

上述灰字交互来自 [zsh-autosuggestions 官方说明](https://github.com/zsh-users/zsh-autosuggestions#usage)及其[历史前缀策略](https://github.com/zsh-users/zsh-autosuggestions/blob/master/src/strategies/history.zsh)。完整 zsh 补全依赖 shell、工作目录、命令和本机文件，不等同于 DUT 的实际环境；不移植本机补全结果，也不为了补全偷偷向串口发送探测命令。

### 3.4 RAW 的验收边界

RAW 是设备端编辑，LINE 是本地编辑。RAW 不启用本地历史接管上下键，不把本地删除画成设备已执行的删除。修复方向键路由后，用真实字节回放核对 `0x08/0x7f`、BS-space-BS、CR、erase-line、cursor move、delete/insert-character 等设备实际输出，补齐所需显示行为和远端光标。

终端显示投影与原始日志分离：设备擦屏/覆盖不能删除原始日志；搜索仍可回到历史证据。是否采用完整 VT 解析器，要依据录制字节样例验证兼容与性能后确定，避免以零散字符串替换模拟终端。

## 4. 本次会话全量搜索与退出清理（新增搜索问题、#15）

### 4.1 用户可见语义

- 默认搜索当前串口“本次打开至当前”的完整已采集日志，而不是当前屏幕或内存缓存。
- 提供“本次会话所有串口”切换；跨端口命中显示端口、时间和机型，跳转后保留返回路径。
- “全部保留档案”作为额外范围，区别于本次会话。界面直接显示起止时间和可用覆盖范围。
- 实施选用每端口的本地会话磁盘归档，初次打开先建归档再接收初始回放；起点为本次实际接收的第一条回放记录。同一 TUI 仍打开时，重连/daemon 重启在原归档增加范围和边界，不因内存淘汰或服务端 retention 删除已采集内容。

### 4.2 完整性与性能

建立会话磁盘归档上的搜索任务和分页索引。内存缓存仅用于快速显示；默认字面搜索在后台覆盖本次已采集会话。批次预算只用于让出执行权，不是整个搜索的终止条件。

扫描中显示已发现数量和进度；只有范围完成且无缺口才报告完整性。每轮扫描固定 head，完成后增量追踪新日志，避免持续输出导致永远无法完成。更改查询、切范围和退出取消旧任务；旧结果不能覆盖新查询。原有 archive/Run/正则搜索保持单独的范围与有界查询，不把默认会话搜索的全量保证扩大到未采集的全部服务端档案。

结果存储准确 occurrence 位置，不只返回匹配事件。索引和结果页可落盘，UI 只缓存当前附近的少量命中和上下文。最早、最新、百万命中的任意中间页均须可导航，不能固定保留最新 10,000 项。新日志增量加入索引；已选择的旧命中保持稳定。

匹配采用统一的文本投影与源映射，覆盖 ANSI、UTF-8、CR/退格、跨 event、跨查询页、跨日志段，以及长行的人工存储分段。真实端口、epoch、generation 或日志缺口边界不能被拼成一条连续匹配。不得直接把当前 raw-byte archive contains 查询当成与屏幕文字等价的搜索。结果锚点保留 server/session/port/epoch/seq/offset，界面换行与窗口 resize 不改变定位。

归档复用同一显示解析器的 completed/pending 批次：完成行只追加一次，未完成尾行替换，不按每个 RX chunk 重复保存。点击早期命中按需加载前后上下文到主输出栏，继续上下翻阅，而非只显示孤立命中行。退出清除装饰与任务，保持阅读位置；高亮不烘焙进长期快照。

### 4.3 日志保留

当前 daemon journal 默认上限为 10 GiB。此次选用受管理的客户端会话磁盘归档，不增加服务端保留租约：这样已采集记录与 daemon 轮转解耦，重连也不丢之前看到的内容。临时归档目录权限受限、路径唯一；正常结束只清理本次自己创建的目录，发生记录故障时保留以便排查。磁盘开销随当前打开会话增长；关闭后需跨客户端回溯的历史仍遵循 daemon journal 的保留范围。

容量不足、记录失败或已清理历史必须明确显示缺失区间和原因；不能把缺失区间当成零命中。搜索不能补回从未采集或已经删除的数据。磁盘耗尽不能卡住串口收发，但必须暴露日志完整性故障。

## 5. Macro 自动化脚本（#8、#13，承接 #9）

### 5.1 产品与执行模型

宏是平台保存、可审阅、可参数化的串口自动化程序。`command_sequence` 继续适合临时的线性命令链；宏支持条件、循环、等待和复用，不依赖 AI 在每次循环中重新调用 MCP。

公开工具统一命名 `macro_*`。宏功能通过验收并提供迁移模板后，从 tools/list、dispatch、文档和宿主权限示例中删除公开 `trigger`。保留并抽取原 Trigger 的低延迟 RX 监听、唯一 writer、定时调度、取消排空实现，作为宏运行时底层能力。

脚本在 seriald 中执行：可读脚本解析为有源位置的 AST，先静态校验再由受限解释器运行。宏直接操作串口原语，不调用宿主机 shell/Python，不拥有任意文件/网络访问。用户要求的 `for/while/if-else` 从首个完整版本支持。

### 5.2 语言能力

- 参数、`let` 变量、字符串/数字/布尔值、比较与布尔表达式；`if/else`、`for`、`while`、`break/continue` 等基本控制流。
- `cmd(text)`：普通命令的唯一发送入口，自动追加有效 Profile EOL，只等 TX 确认，不等待提示符。不开放 raw/no-EOL，禁止嵌入控制字节绕过约束。未配置 EOL 时用平台默认值；显式禁用 EOL 的旧配置执行前拒绝，不退化成 raw。
- `watch(pattern)`：持续观察本轮新 RX；字面值直接使用字符串，机型提示符使用 `prompt("uboot")`。首版不扩展为任意外部数据源或无界正则系统。
- `wait(watcher, milliseconds)`：命中立即返回 true；本次等待时间到返回 false，watcher 继续观察。断线、数据缺口不能伪装成普通 false。
- `expect(watcher, milliseconds)`：要求期限内可信匹配，否则停止整个宏，不能把普通 wait 超时后继续执行误作成功。
- `delay(milliseconds)`：让出调度器的延时。参数通过 `args.name` 读取，不把参数拼接到脚本源码。

不加入 send_keys、send_line、raw、每步 eol 或另一个 input 工具。人按 Ctrl-C/Ctrl-D 与现有 MCP signal 是独立控制信号路径，本轮不扩展为宏的按键语言。

条件必须有串口证据。watch 在下一条 cmd 写入前由 daemon 原子安装，观察起点绑定该 TX 后的新 RX；AI 不配置 cursor/scope。跨 event 提示符连续匹配，旧 U-Boot 日志不能让本轮成功。watcher 命中后保持 matched，后续阶段新建 watcher，不复用已命中的旧条件。每次发送前处理已到达的匹配事件；在途写入等待确定结果再报告终态。

执行建议默认 30 秒、最多 120 秒；这是新宏产品限制，不是 MCP 协议的统一上限。另有内部指令、TX 总量和内存预算，脚本不必给每个 while 重复写预算。空循环也能打断，达到任何总预算明确失败。等待不忙轮询；写入不确定、RX gap、Run/控制权丢失等完整性错误终止执行。

### 5.3 U-Boot 示例（Macro Script v1）

```text
let boot = watch(prompt("uboot"));
cmd("reboot");
while (!boot.matched) {
    cmd("slp");
    wait(boot, args.interval_ms);
}
```

reboot 和 slp 都自动加 EOL。这里的 reboot 是示例设备命令；旧 Trigger 的 kickoff 字段不是设备命令的一部分。实际重启命令按机型配置或参数提供。cmd 不等 shell 提示符，重启后可以及时开始 slp 循环；watch 提前安装，不能等发送结束才监听。prompt("uboot") 必须从当前机型 Profile 解析，否则执行前报错、零 TX。实际提示符和发送间隔需要真机验证。

### 5.4 MCP 工具

| 工具 | 行为 |
| --- | --- |
| `macro_list` | query 查找/分页列出共享摘要；按 id 返回完整脚本、参数、revision；include_drafts 显式查看未共享草稿。 |
| `macro_save` | 创建或修改合法宏，内置语法/参数校验。新建默认 shared:false；更新需 expected_revision，省略 shared 保留原状态。 |
| `macro_run` | macro_id + revision 或一次性 script 二选一；在现有 Run 内同步等待最终结果。inline 不入库。 |

只增加三个公开工具。校验内置于 save/run；停止复用 Run 中止、MCP 取消和 TUI/App 停止入口。不增加独立 status/cancel/validate/delete 工具，不要求 AI 轮询后台任务。

查找：macro_list({"query":"uboot"})；读取编辑：macro_list({"id":"enter_uboot"})。

保存参数示例：

```json
{
  "id": "enter_uboot",
  "name": "进入 U-Boot",
  "description": "发送 reboot，再重复 slp，直到匹配当前机型 U-Boot 提示符",
  "parameters": {
    "interval_ms": {"type": "integer", "default": 50, "minimum": 20, "maximum": 1000}
  },
  "script": "let boot = watch(prompt(\"uboot\"));\ncmd(\"reboot\");\nwhile (!boot.matched) {\n  cmd(\"slp\");\n  wait(boot, args.interval_ms);\n}",
  "shared": false
}
```

返回 id 和 revision，例如 enter_uboot、1。id 冲突不随机创建重复条目，提示读取现有定义。修改仍调用 macro_save，提交完整定义并附 expected_revision:1；并发冲突不覆盖更新。非法文本留在 UI 编辑草稿，保存接口拒绝并指出行列。

执行已保存宏：

```json
{
  "run_handle": "<当前已授权 Run>",
  "macro_id": "enter_uboot",
  "revision": 1,
  "args": {"interval_ms": 50},
  "timeout_seconds": 15
}
```

一次性运行（不保存、不进入列表）：

```json
{
  "run_handle": "<当前已授权 Run>",
  "description": "本次进入 U-Boot",
  "script": "let boot = watch(prompt(\"uboot\"));\ncmd(\"reboot\");\nwhile (!boot.matched) {\n  cmd(\"slp\");\n  wait(boot, 50);\n}",
  "timeout_seconds": 15
}
```

inline 首版直接接收完整脚本，不再要求临时参数 schema。保存的宏支持 string/integer/boolean 参数和默认值/范围。语法、参数类型、revision、Profile 条件或机型适用性等执行前校验失败时零 TX；运行中的动态错误可能已发送，不能把所有失败说成“没有执行”。

工具返回最终成功/超时/人工中断/失败、最后源码行、已发送数量和串口证据范围。operation id 复用现有审计/重试约束；网络结果不确定时不盲目重跑宏。

### 5.5 简单目录规则与执行一致性

宏目录由 seriald 统一持久化，TUI/App 与 Agent 使用同一脚本格式和保存接口。人可以查看、编辑、保存、试运行，Agent 同样可以。目录保留稳定 id、名称、用途、参数定义、script、语言版本、revision、来源与更新时间；可选 applies_to 声明适用机型，不按串口另建目录。

防止一次性脚本污染共享列表，采用最少规则：

- 一次性任务直接 inline run，不入库。
- 需要继续编辑的保存为合法但未共享的草稿；shared:false 不进入默认列表或初始化上下文。草稿可按 id 试运行；shared 只控制目录曝光，不是权限边界或“人工认证”标记。
- 只有显式 shared:true 才进入平台共用目录。先查已有宏、优先复用；实验修改共享宏时先 inline 验证，再带 revision 更新。
- 共享宏以 run_handle 选择端口；COM、临时 IP、文件名等按需求参数化，设备条件优先引用 Profile。工具做格式/类型检查，不能宣称能静态证明脚本“完全通用”。
- TUI/App 默认显示共享宏，可切“显示草稿”；可查看源码、用途、适用机型、参数和 revision。人可以审核修改并显式共享，不引入多级审批、评分、认证或独立发布流水线；首版没有独立保存者身份/认证系统。

运行固化 script/AST/参数/Profile 与 revision，并发编辑不影响正在执行的脚本。设备身份、generation、控制权或 Run 变化则中止，不偷偷切目标。单口只允许一个前台自动化执行；其他 Agent 物理操作报忙、不排队。宏内部步骤不逐步再请求 MCP。

公开 macro_run 同步返回终态，内部运行期间控制连接继续续租。普通 run_end 在执行中报告忙；显式中止或 MCP 取消停止后续动作并收敛在途写入；连接丢失按现有 Run 失联规则中断，不能脱离原控制权长期占用串口。

Human Enter/RAW/Ctrl-D 介入时停止后续宏动作，收敛在途 TX 后串行处理人工输入，返回 interrupted_by_user 并说明“用户使用了命令”或具体控制键。Agent 重新 command/macro 前必须 live read，宏不能盲目从下一行续跑。断线/崩溃不自动重放。

操作记录保留宏 id/revision、源码行、累计发送次数与证据范围；每次 slp 的原始 TX 不丢失，宏页面显示执行进度。宏步骤不进入人工输入历史。首版不承诺将每种循环结构还原成可折叠执行树。源码与参数可审阅，不鼓励保存密码等敏感字面量，本轮不另建 secret 管理平台。

### 5.6 提前向 AI 提供宏上下文

初始化上下文只注入共享宏摘要：宏名、id、revision、用途、参数摘要和适用条件，不注入草稿和全部脚本。目录较大时明确总量/截断及 macro_list 查询入口。

默认指导是“先查已有宏；一次性 inline run；需要复用再参数化 save；显式 shared 才进入公共目录”。initialize instructions/工具描述提供规则和短目录，正常 devices/run_start/macro_save 返回最新目录版本与摘要，macro_list 提供完整定义。执行核对所选宏 revision，无关宏更新不使当前宏失效。

人保存后，通过正常工具结果刷新目录是基础兼容路径。支持标准 MCP tools/list_changed 的宿主可接收短目录变更；现服务端尚未实现通知广播，完成发送/订阅链路和真实宿主验证后才能声明支持。此处仅做 serial-platform 宏发现，不修改已暂缓的 OpenCode 审批 UI。

不能保证所有 MCP 客户端自动将资源或 prompt 放入模型上下文；测试所支持宿主的新会话发现、已有会话更新、草稿不混入默认目录，不能只验证 tools/list 字符串包含宏名。

## 7. 其他独立修复

- #10：当前串口配置字段按 Enter 校验、提交、生效；共享 Profile 修改继续显示影响范围确认。创建/删除保持完整事务；revision 冲突不覆盖新配置，失败保留输入。

- Ctrl-D：LINE 漏处理，RAW 已编码为 0x04。按第 3 节修复人工按键并同步 App；现有 MCP signal 已有 ctrl_d，不另增公开工具。验证 Agent 活跃/不活跃时实际字节与 read gate；“设备退出当前程序”取决于设备状态，不能等同于“传输成功”。
- #12：TUI/App 具体机型名统一高亮身份样式，未配置状态单独显示；验证深浅色、长名称和窄屏。
- #16：read 增加 exclude_patterns，以区分大小写的字面子串匹配并隐藏完整噪音行，默认关闭，不自动猜忽略时间戳/空格。只过滤返回视图，journal/search/command/宏 matcher 不受影响；返回计数、规则、警告和可回查范围。不完整边界行保留；人工介入恢复读取旁路过滤，保持 read gate 的上下文意义。

### 8.1 必测交叉场景

- 人工历史：TUI 提交后 App 可见且切端口不隔离；Agent command/sequence、任何宏步骤、RAW 信号均不混入。并发提交、重启、操作去重、accepted/rejected/uncertain 不混淆。
- 输入 UE：输入/搜索/候选/Agent 历史/RAW 全状态按键回放；右箭头行尾接受、行中移动，Enter 不发未接受灰字，候选确认不发命令；取消恢复草稿与光标。中文 IME、宽字符/组合字符/emoji、长行滚动、多行粘贴、断线/切端口/旧异步结果不误发送。
- Ctrl-D：LINE/RAW × Human/Agent/idle，真实字节恰为一次 0x04 且无 EOL，保留草稿、不进历史；人工介入后 Agent 必须 read；弹窗不透传。
- 机型树：展开 page 不变且不提交，叶子一次提交完整 family/name；取消、空组、增删、长列表、revision 冲突不选错项。
- 搜索：首尾、百万密集命中、跨 event/UTF-8/ANSI/人工分段、重连、跨 epoch、未结束尾部、容量与磁盘故障；会话磁盘归档独立于 daemon retention；退出无残色且阅读位置不变。保留租约不是本次选用方案，不作为已实现能力。
- 宏执行：watch 先于 reboot、旧提示符不误判、快速提示符不漏、所有 cmd 按 Profile 加 EOL；不同回显、while/for/if、总超时/CPU/TX 预算、空循环、跨 chunk matcher。介入/取消后不调度新 TX，在途结果明确，部分写入不自动重试。
- 宏管理：恰好三个公开工具；非法脚本 save/run 拒绝；inline 不入库、草稿不注入、显式共享才可发现。id 冲突不生成随机重复宏，更新 revision 冲突；执行快照固定；同步运行续租、run_end 忙、显式中止收敛、外部 Agent 写冲突、连接消失中断且不重放。
- 宏发现：新会话能见共享摘要，后续正常工具结果/支持的通知可刷新；草稿需显式查看，Profile 条件缺失执行前零 TX；不依赖修改 #19 审批界面。

性能按响应预算验收：建议仅在草稿/历史变化时计算，不随 RX 或每帧重扫；编辑和取消及时响应，后台搜索不阻塞串口采集/UI。GB 级档案、百万命中和高频 RX 测 CPU、RSS、磁盘、首结果与取消延迟，记录基线后设置门槛。

### 8.2 审查与发布纪律

每个 Issue 独立记录“需求 → 复现/依据 → 设计 → 针对性测试 → 验收结果”。共享键盘状态机、文本投影、端口 actor 明确责任人，避免并行改同一核心文件互相覆盖。

针对性独立审查重点检查误发字节、漏日志、旧上下文匹配、重复写、持久化损坏、焦点抢键。模块通过后再整体验证，不以总测试数替代具体场景验收。

发布使用一次构建的固定工件；上传重试复用已校验工件，不因网络问题重编译。发布前核验 tag/commit、协议版本、精确资产集合。#14 暂缓不等于跳过 Windows RAW/TUI 字节验证；未完成真机验证的场景明确保留未验收状态。
