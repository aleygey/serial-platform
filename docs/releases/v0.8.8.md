# v0.8.8

## 修复与改进

- **跨重开的串口历史搜索**：TUI 默认按当前串口搜索后端仍保留的全部历史，分批读取并在磁盘建立搜索索引；支持旧会话匹配及上下文定位。加载中、日志缺口和部分结果明确提示，不将尚未完成的搜索报告为完整的“无匹配”。当前会话、正则和 Run 范围仍有各自的明确范围提示。
- **Agent 历史持久化与清理**：TUI 和 App 按 Run 保存历史索引。连续两次 Delete 清理所选 Run；即使选中子命令也以整轮为单位。提供清空已结束 Run 的入口，正在执行的 Run 受保护。清理状态由后端持久化，不删除原始串口日志，不影响人工输入历史或灰字补全。旧数据在后台建立索引，未完成时禁止不完整的全量清理。
- **Agent 历史定位与显示**：重开后仍可加载保留日志中的命令上下文；按 epoch 和原始序号精确定位，缺失时明确提示。宏按本次执行分组，重复执行不会混为一组。Run 以颜色表示状态，移除冗余状态文字。鼠标第一次点击未聚焦历史面板只切换焦点，后续点击再展开。
- **TUI 多行输入**：LINE 模式直接粘贴多行到可编辑草稿，不立即发送；Enter 确认发送，支持方向键逐行编辑和终端支持下的 Shift+Enter 换行。保留内部空行和空格，统一使用当前 Profile 的 EOL；超出单次发送限制时保留草稿并报错，不拆分重发。多行草稿不混入单行人工补全历史。RAW 模式的大段或多行粘贴仍需确认。
- **机型与配置快速切换**：机型名、设备交互 Profile、串口 Profile 作为同级入口；增加机型快速选择、查询、最近使用和同页二级机型选择。普通修改确认后立即向后端提交，移除页面底部重复的保存入口；后端确认成功后才显示已生效。共享配置的影响继续明确确认。
- **统一 setup**：在线和离线使用同一套交互式向导，扫描、多选和刷新串口；串口参数、机型名、Shell/U-Boot 命令提示符、EOL 和发送节奏均可通过选项配置。在线提示符候选只来自已经接收的输出，不主动发送探测命令。保留已有值，修改单个串口不覆盖其他串口的共享配置；最后统一确认并原子保存，配置冲突不会部分覆盖。
- **MCP 输出精简**：连续完整日志行仅时间戳不同、正文相同时可折叠显示重复次数和时间范围；原始日志、搜索与宏读取不改变。跨缺口、会话或端口边界不合并。
- **启动诊断**：日志恢复转到后台阻塞任务，启动进度区分恢复阶段；仅对确实仍在恢复的本次子进程适当延长等待。保留有界启动错误日志，启动失败时便于定位，不结束其他进程。

## 升级注意与范围

- 请同时更新发行包中的 serial、seriald、serialctl、serial-mcp 与 App，并重启服务；wire protocol 仍为 **9**，但新增历史和 setup 接口需要本版后端，不建议与旧组件混用。
- 不需要删除配置、宏或原始串口日志。Agent 面板的“清理”只隐藏对应历史记录，不释放原始日志空间。
- 历史搜索覆盖的是**后端仍保留的日志**，不是无限保留；已被保留策略删除的原始内容无法恢复。本版尚未加入可配置目录、按日期或大小轮转的独立 `.log` 自动存档。
- Windows 真机启动问题的最终确认、GB 级长时间性能验证仍需后续验证；本版提供启动诊断和恢复改进，不宣称所有硬件场景均已解决。
- #14 与 #19 继续暂缓。
