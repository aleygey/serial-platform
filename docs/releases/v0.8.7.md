# v0.8.7

## 修复与改进

- #22 / #23：宏不再被历史日志降级标记永久阻断。日志写入超时后继续跟踪真实落盘结果，后续落盘成功可恢复健康状态，不需要重启或清日志。宏使用实时 RX，遇到真实流缺口、断连和人工介入仍停止。
- 宏输入校验：普通 `cmd(text)` 检查完整、精确命令回显；缺字或无法确认时停止后续步骤，报告源码位置和有界观测内容，不自动重发。仅检查输入，不判断命令结果。
- #21：退出 Agent 历史、隐藏历史或回到输入区后，清除缓存的命令背景高亮，保留串口文本及当前位置。
- #24：支持点击串口标签、Agent 历史条目和输入区切换焦点；弹窗阻止底层点击穿透，历史点击不会发送串口命令。
- #25：默认 Monitor 列表只显示运行中任务，历史仍保留。TUI 历史焦点下按 F6 显示/隐藏已停止任务，选中已停止 Monitor 后连续两次 Delete 显式删除其历史。MCP `monitor_stop(delete_history:true)` 提供同样的清理能力。删除 Monitor 历史不删除原始串口日志。
- Setup：本地离线三步向导自动枚举串口，支持刷新、多选、手动输入、稍后配置、波特率/EOL 与可选高级设置、保存前确认；不覆盖未选择的已有端口和 Profile。运行中的后端或远程地址使用在线配置与后端扫描。扫描不打开串口、不发送探测命令。
- MCP 宏说明直接描述当前工具能力，不再依赖旧工具的迁移背景。

## 升级注意

- wire protocol 升至 **9**。请同时更新 serial、seriald、serialctl、serial-mcp 与 App，重启服务并刷新 MCP 工具列表，不要混用 0.8.6 组件。现有配置、宏目录和串口日志保留，无需删除。
- `cmd(text)` 现在最多等待 2 秒确认完整回显；宏总超时仍优先。缺乏设备回显时无法证明设备收到完整命令，不会虚报校验成功。
- 对明确无回显的场景（例如 reboot 后反复发送 slp 的启动窗口），人工/Agent 审核后使用 `cmd(text, "send_only")`。该模式保留 EOL，只保证主机侧发送，不验证设备输入，也不判断执行结果。旧宏不会被自动改写。
- 宏结果增加 `input_verified_writes` 和 `send_only_writes`，与总发送数 `writes` 分开显示。匹配到提示符不代表设备业务操作成功。
- #14 与 #19 本版本继续暂缓。

## 验证范围

Rust 全工作区回归、严格 Clippy、App 类型检查/单元测试/构建，以及 Jenkins 四平台打包。串口行为通过模拟驱动测试覆盖慢日志/文件切换、缺字回显、正确回显后设备报错、人工介入等场景；不宣称已在所有真实硬件上验证。
